# rfnry-senses — design

Written 2026-09-24 from the brainstorm of the communication cycle (approved decision by decision in
conversation). A from-scratch library that fuses and replaces rfnry-speech (`../rfnry-speech`, ~7.9k
lines of source) and rfnry-vision (`../rfnry-vision`, ~6.3k lines). This document says what is kept;
everything not named here is stripped. Depends on the family content parts (engine
`docs/plans/2026-09-23-content-parts-design.md`) and on the `Identity` block defined in rfnry-thread's
design.

## 1. What the library is

rfnry-senses gives a model eyes, ears and a voice in real time. A **session** connects a person's
microphone and camera to a model and the model's voice back to the person. The assistant is a
first-class presence: it can speak first, look when it has a reason to, and be interrupted like
anyone in a conversation. Acting first and answering are the same API.

A session is **input and output only**. It hears, sees, speaks and reports what happened; it does not
decide what to say. The loop that decides — an engine agent, a plain model call, a live model's own
reasoning — lives outside it. Its tools reach the rest of the family (`ThreadTools`, `MemoryTools`,
an engine agent as a tool) through the shared `Tools` shape; senses imports none of them.

### Why one library

Realtime models are converging on one session that hears, sees and speaks at once. Separate speech
and vision libraries would need glue to feed one live model from two sessions — the most important
code, living in neither. One session carries audio and video together, on one clock, with one
attribution rule and one event stream. Modalities are optional per session.

### Not in scope (stripped from the old libraries)

The `@respond` handler loop, handler and tool registries, runs and failure codes; the event stores
(`SpeechStore`, `VisionStore`, in-memory and filesystem), blob storage, the recorder, retention
sweeps, the content codec and `OpaqueEvent`; telephony μ-law/A-law codecs; one-shot STT/TTS helpers;
the general-purpose rgb24→JPEG transcoding wrapper (the WebRTC extra still encodes its camera
track's frames, §8); the tenant path-jail; telemetry; the optional capability
protocols (`SupportsNativeSay`, …); `TurnDetector`; both React packages (hooks, providers, zustand
stores, visualizers, analyser bus, error boundaries, device pickers); the wire-fixture generator
script as a separate tool (fixtures stay, generated by tests).

## 2. Family shapes (copied, never imported)

Byte-identical with the other libraries, pinned by `test_family.py`:

- **Content parts**: `Text`, `Image`, `Audio`, `Document`, `Part`, `Content`.
- **`Tool` / `Tools`**: for `SensesTools` and for the tools a live model receives.
- **`Identity`** (as in rfnry-thread): `role: user | assistant | system`, `id`, `name`, `metadata`.
- **Decision contract** (from engine/memory): `DecisionModel`, `Check`, `CheckAnswer`, `Decided` —
  only what turn completion needs is exported. The copied source is the contiguous family blocks
  those four depend on (`State`, `Usage`, the `Choice` … `Decided` block, `as_decided`, the answer
  and usage `…Like` protocols), so each block stays byte-identical with rfnry-engine; the rest stays
  unexported.

Errors: root `SensesException`; children `InputError`, `ConfigurationError`, `ModelError`,
`TransportError`, `NotFoundError`. Rule-9 messages.

Tenancy: `scope: str`, the engine's word. A session belongs to one scope, named by the consumer's
authenticated endpoint and handed to `serve` or `accept_offer`. Senses stores nothing, so tenancy is carried on the session and its events rather
than enforced in storage.

## 3. The model contracts

Named for what they produce, like the family's `GenerationModel`, `DecisionModel`,
`EmbeddingModel`:

```python
class LiveModel(Protocol):
    async def open(self, *, tools: list[ToolSpec], instructions: str | None) -> LiveConnection: ...

class LiveConnection(Protocol):
    async def send_audio(self, frame: AudioFrame) -> None: ...
    async def send_image(self, image: Image) -> None: ...
    async def send_text(self, text: str, *, respond: bool) -> None: ...
    async def say(self, text: str) -> None: ...
    async def interrupt(self, played_ms: int) -> None: ...
    async def submit_result(self, call_id: str, result: Content, is_error: bool) -> None: ...
    def events(self) -> AsyncIterator[LiveEvent]: ...
    async def close(self) -> None: ...

class TranscriptionModel(Protocol):
    def stream(self) -> Transcription: ...

class Transcription(Protocol):
    async def feed(self, frame: AudioFrame) -> None: ...
    def events(self) -> AsyncIterator[Transcript | UtteranceEnd]: ...
    async def close(self) -> None: ...

class SpeechModel(Protocol):
    def speak(self, text: str) -> AsyncIterator[AudioFrame]: ...
```

- `LiveEvent`: `LiveAudio` (audio out), `LiveHeard` (the person's transcript, partial/final),
  `LiveSaid` (the model's transcript), `LiveStarted`/`LiveDone` (every response bracketed; an adapter
  whose vendor has no markers makes them), `LiveToolCall`, `LiveInterrupted`, `LiveFailed`.
- `send_text(respond=True)` backs `prompt`; `respond=False` backs `inform`; `say(text)` backs a live
  `say` — verbatim speech is a vendor technique (a native call, or an instruction to repeat), so it
  lives in the adapter, not in a prompt the library writes. (Added while writing the docs: the
  first contract had no method behind the live `say` row of §4.) The connection's `say` takes whole
  text: a streamed session `say` (§4) is joined before it reaches it.
- Transcription events: `Transcript(text, final)` and `UtteranceEnd()`.
- A `LiveConnection` implements everything; a vendor that cannot (e.g. truncate) raises from its
  adapter. No capability matrix.
- **Turn detection** has no protocol of its own: acoustic end of speech is the transcription model's
  `UtteranceEnd`; semantic completion ("they paused but are not done") is an optional
  `DecisionModel` `Check` on the running transcript. Cascaded voice works with transcription and
  speech models alone; a decision model makes turns smarter; a generation model is never asked to
  judge turns.

`AudioFrame(data: bytes, sample_rate: int, channels: int)`; audio is PCM16 inside the library.
Images are the family `Image` part.

## 4. The session

Two modes, chosen by the models given:

- **Live** — `Session(live=LiveModel, instructions=...)`, started with `start(tools=Tools|None)`:
  the model runs inside the vendor's session; senses pipes audio and frames in, audio out, and dispatches the live model's tool
  calls through `tools` (any family `Tools`: an engine agent as a tool, `ThreadTools`,
  `MemoryTools`, product tools).
- **Cascaded** — `Session(transcription=..., speech=..., turns=DecisionModel|None)`: senses hears,
  transcribes, detects turns and emits them; the consumer's loop decides and calls `say`.

`Session(transport, ...)` takes the transport `serve`/`accept_offer` returned and its scope from it
(`session.scope`); `start(tools=None)` opens it — the live connection, with the tools' definitions —
and it is an async context manager (`async with Session(...) as session` starts one without tools;
on a started session it only closes) and `close()` ends it early. Audio follows the models — a session with no model that hears or speaks
drops audio; `video=False` by default. A camera-only session has no models at all. (The separate
`audio=` flag was dropped while writing the docs: it had no setting that meant anything.)

**Primitives** (every action takes `triggered_by: Identity`):

| method | live | cascaded |
|---|---|---|
| `say(text)` — a `str` or an `AsyncIterator[str]` | speak exactly these words (a stream is joined, then sent) | synthesize (streaming, sentence by sentence) and play |
| `prompt(text)` | ask the live model to respond now, in its own words; returns `Said` | not available (`ConfigurationError`) |
| `inform(text)` | add context the live model sees, without speaking — replaces stale connect-time instructions | not available |
| `interrupt()` | stop speaking and truncate to what the person heard | same |
| `mute()` / `unmute()` | output gate: nothing reaches the person while muted | same |
| `look(frames=1)` | the newest frame(s) from the window, each an `Image` part followed by `Text("frame at 12:03:04.200")`; an empty window is `NotFoundError` | same |
| `events()` | the session's event stream | same |
| `close()` | end the session | same |

Every action leaves an event naming its cause: `say`/`prompt` → `Said`, `interrupt` →
`Interrupted`, `mute`/`unmute` → `Muted`, `look` → `Looked`, `inform` → `Informed`. `close()` and
`events()` take no cause.

**`say` returns what was heard.** When playback ends it returns `Said(text, heard, interrupted)`: the
text the person actually heard before cutting in, from the client's `played_ms` and a ledger of
synthesized chunks. The same truncation drives the live model's `interrupt(played_ms)` so its
context holds only what was heard.

**`say` takes streamed text.** `say(text: str | AsyncIterator[str], *, triggered_by)` — a text
mind's reply can be spoken while it is still being written. In cascaded mode the chunks go through
the same sentence splitter (a sentence is complete once text follows its end), so synthesis starts on
the first complete sentence and the rest follows as it arrives. In live mode the chunks are joined
and sent once the stream ends: the connection's `say` takes whole text, because verbatim speech is a
vendor technique that needs the words it repeats; the cause joins the FIFO when the text is
complete. Either way `Said` reports what was heard, and `Said.text` is what the voice was given.
When the utterance is cut, senses stops reading the stream and closes it (`aclose()`, when it has
one). A stream that yields no text speaks nothing and returns an empty `Said`.

**Barge-in.** In cascaded mode, a new utterance from the person while the assistant speaks clears
outbound audio, waits briefly for `played_ms`, records what was heard, emits `Interrupted`, and fences
stale synthesized frames by a generation counter. In live mode the vendor detects the interruption;
senses truncates with the client's `played_ms`. The counter numbers every utterance and rides in
the audio frame header, so the client drops in-flight frames of a stopped utterance too. When no
`played` arrives within 0.25 s, senses estimates it from its own clock (audio sent, capped by the
time since the utterance started) — an interruption never waits on a silent client. `mute` while
speaking stops and truncates the utterance the same way.

**The frame window.** Video frames are kept for a short window (default 10 s, byte-capped), evicted
by the session's own clock, never sampled or described by the library. `look` reads from it. In
live mode frames also stream to the model.

**Attribution.** `triggered_by` is required on every action. In live mode, `say`/`prompt` push their
cause onto a FIFO; each response the model starts takes the oldest; an empty queue means the model
answered what it heard or started on its own, and the cause is `None` — declared, never assumed.
(Changed while writing the docs from naming the assistant as the cause: with vendor turn-taking an
empty queue most often means the model is answering the person, and naming either party would be a
guess; the family rule is that unsolicited turns stay unattributed.) Pushing onto the FIFO and
sending to the connection happen under one lock, so concurrent `say`/`prompt` calls keep order.

## 5. Events

```python
async for item in session.events():
    match item:
        case Heard(text=..., final=..., speaker=Identity): ...
        case TurnEnded(text=..., speaker=Identity): ...
        case Said(text=..., heard=..., interrupted=..., triggered_by=Identity | None): ...
        case Interrupted(heard=..., triggered_by=...): ...
        case Speaking() | Silent(): ...
        case Looked(frames=..., triggered_by=...): ...
        case Muted(muted=..., triggered_by=...): ...
        case Informed(text=..., triggered_by=...): ...
        case ToolCalled(name=..., input=..., output=..., is_error=...): ...   # live-mode tool dispatch
        case Closed(reason="closed" | "hung_up" | "failed", message=...): ...
```

- Every event carries `scope` and `at`. `events()` is a broadcast: each call sees every event from
  then on. The client receives every event except `Informed` and `ToolCalled`.
- `TurnEnded(text, speaker, probability)` is cascaded only; `probability` is the decision model's
  answer, `None` without one. Below `turn_threshold` (0.5) the session waits for more speech, and
  ends the turn anyway after `turn_timeout` (3 s) of silence.
- `Heard` is emitted from the transcription stream whether or not the model answers — the person's
  words are never lost because the model chose silence.
- Nothing is stored. A consumer that wants a record mirrors events into a thread (a few lines,
  shown in the docs and an example); the engine's Refinery records an agent's side.

## 6. SensesTools

For a *text* mind — an engine agent or any tool loop — driving the room:

```python
tools = SensesTools(session, triggered_by=ana)
```

| tool | returns |
|---|---|
| `look` | `[Image(jpeg), Text("frame at 12:03:04.200")]` — the model sees the frame itself |
| `say(text)` | `{"heard": ..., "interrupted": ...}` |
| `prompt(text)` | `{"said": ..., "heard": ..., "interrupted": ...}` — live sessions only |
| `inform(text)` | `"informed"` — live sessions only |
| `interrupt()` | `{"heard": ...}`, empty when nothing was being said |

`definitions()` offers what the session can do: `look` with `video=True`, `say`/`interrupt` with a
voice (live or a speech model), `prompt`/`inform` when live. The `say` tool takes
text only — a model's tool arguments are a string; a streamed `say` is for code. There is no `listen`
tool (the loop is started with what was said) and no `watch` tool (triggers are the consumer's).

## 7. The two-minds pattern (documented, built from family parts)

A live model in front and an engine agent behind:

```python
session = Session(link, live=live_model, video=True)
consult = engine.tool("core", scope="acme", name="consult", tools=SensesTools(session, triggered_by=assistant))
await session.start(tools=consult + ThreadTools(client, thread_id=t, triggered_by=ana))
```

- The live model asks the text mind with `consult` (an engine agent as a tool — see §10).
- The text mind speaks through the live voice with `say` (verbatim) or `prompt` (its own words), and
  keeps the live model current with `inform`.
- Either mind looks with `look`; the text mind sees frames directly — no separate vision model.
- The shared transcript both minds read is the thread (mirrored from `events()`).
- Product rules (a mandate gate, a floor policy, a persona) stay in the product; they use `mute` /
  `unmute`, `interrupt` and their own tools.

## 8. Transports

One public `Transport` protocol, the same shape for both (`identity`, `scope`, `inbound()`,
`send_audio(frame, utterance)`, `send_control(dict)`, `clear_audio()`, `close()`), so a consumer's own
line — telephony, a meeting bridge — is a transport of theirs. `serve(connection, identity=,
scope=)` takes the person and scope the consumer authenticated on the upgrade, reads the hello
(the protocol version, nothing else), and returns the transport (or `None`, after an `error`
frame); the consumer then builds the `Session` on it. The
connection has four methods — `receive() -> str | bytes`, `send_text`, `send_bytes`, `close` —
not the family's `receive_text`/`receive_bytes` pair: a media socket interleaves text and binary
frames, and a caller cannot know which `receive_*` to await next (Starlette's `receive_text`
raises on a binary frame). (Both corrected while writing the docs: `serve` returning the
transport keeps the session and its loop in the consumer's hands without a session-factory
callback.)

- **WebSocket** (core): binary frames with a small header — audio `[1][channels u8][sample_rate
  u32 LE][utterance u32 LE][PCM16 LE]`, camera `[2][JPEG]` — plus JSON control frames: `hello
  {protocol}` and `played {utterance, ms}` from the client; `ready`, `speaking
  {utterance}`, `silent {utterance}`, `stop {utterance}`, `event {event}` and `error {message}` from
  the server. The client answers `stop`, and the natural end of an utterance (`silent`), with
  `played`. Media uses its own socket, separate from any thread socket.
- **WebRTC** (extra `rfnry-senses[webrtc]`, aiortc): one peer connection with an audio track and an
  optional video track at the client's `fps`; controls on the data channel, the client's `hello`
  first; `accept_offer(sdp, identity=, scope=)` returns the transport with its `answer` SDP (the
  consumer hosts and authenticates the signalling endpoint; the client posts `{sdp}` and reads
  `{sdp}`). The extra resamples inbound audio to
  `sample_rate` and encodes the camera track's frames to JPEG at the client's rate with the `av`
  aiortc already brings — the stripped item in §1 is the old general-purpose rgb24 wrapper, not
  this. Recommended for browser voice: Opus bandwidth, loss concealment, and echo cancellation that
  makes barge-in work on speakers.
- **Loopback** (core): an in-process transport for tests and for sources that are not a browser;
  it records what the person would receive and answers `stop` with `Played`.

The transport is an explicit choice, never negotiated. Camera-only sessions use WebSocket JPEG at the
rate models consume (default 1 frame/s).

**Authentication lives entirely at the consumer** (as in rfnry-thread; superseding the hello-token
design of commit 7462388). There is no `authenticate` callback, no credential in the hello and no
authentication deadline. The consumer authenticates the WebSocket upgrade with their own framework
— cookies, headers or a token, over TLS — and hands the accepted socket to `serve(connection,
identity=, scope=)`. The WebRTC offer endpoint is the consumer's own HTTP endpoint, authenticated the
same way, which calls `accept_offer(sdp, identity=, scope=)`. The TypeScript client connects with
whatever the endpoint expects: cookies on their own, a WebSocket token as a subprotocol
(`protocols`), headers on the WebRTC offer request (`headers`); Python clients and tests pass
`headers=`. The docs carry the consumer's checklist: `wss://`; with cookies, check the upgrade's
`Origin` (cross-site WebSocket hijacking); prefer short-lived tokens. `identity` and `scope` are
keyword-only on both (decided while folding this in: the call reads as who and where, and a
positional swap of two plain values is not caught by types when `Identity` is built inline).

**Seeing as video.** Today's live models take video as a sequence of image frames. "Seeing as
video" is frames streaming to the live model continuously, at the rate the consumer sets (`fps` on
the client): every frame that arrives goes to the model, the newest when it falls behind. The two
transports carry those frames differently. WebSocket sends each as a JPEG — light, and ideal at 1–2
frames a second. WebRTC sends a real video track, with inter-frame compression and adaptive
bitrate — the right path when a product raises the frame rate; the extra turns the track back into
JPEG frames on the server. A future model that takes true video input would add `send_video` to
the live contract, additively; nothing here changes.

## 9. The TypeScript client — `@rfnry/senses`

Framework-free:

- `connect({url, transport: "websocket" | "webrtc", protocols?, headers?})` — `protocols` are the
  WebSocket subprotocols (a token, when the endpoint takes one), `headers` go on the WebRTC offer
  request; cookies need neither.
- Microphone capture with `getUserMedia` echo cancellation and noise suppression; camera frames
  sampled at `camera.fps` (default 1) as JPEG over WebSocket, or a video track capped at `fps` over
  WebRTC — sent continuously while the camera runs, which is how a live session sees as video.
- Playback that tracks `played_ms` and reports it on interruption automatically.
- `mute()` / `unmute()`, `pauseCamera()` / `resumeCamera()`, `setFps(fps)` — the WebSocket path
  changes the sampling interval, the WebRTC path calls `applyConstraints({ frameRate })` on the
  camera track; without a camera it throws.
- `subscribe(listener) -> unsubscribe` for the session's events (every one but `Informed` and
  `ToolCalled`) and `{kind: "status", status: "open" | "closed"}`.

Out: framework bindings, stores, visualizers, analyser utilities, device pickers, UI.

## 10. Engine addition: an agent as a tool

A small change to rfnry-engine (its own commit, before senses needs it):

```python
tools = engine.tool(agent, *, scope, name=None, description=None, context=None, tools=None, workspace=None) -> Tools
```

The tool's body runs `engine.run(agent, scope, input=args["input"], context=context)` and returns
the reply (or a decision's answers as a dict). It records like any run. It is how a live model
consults an engine agent, and how any runtime mounts an agent. It returns a one-tool `Tools`, not a
`Tool`: a `Tool` has no `+` and is not a `ToolsLike`, so `consult + ThreadTools(...)` and
`session.start(tools=consult)` would not work (aligned with the engine plan,
`engine/docs/plans/2026-09-24-engine-tool-plan.md`).

## 12. Tests

Unit: scripted fake live, transcription, speech and decision models; an in-process loopback transport;
barge-in truncation with a fake `played_ms`; a streamed `say` spoken as its sentences complete and
stopped mid-stream by a barge-in; turn detection with and without a decision model; the

## 13. Decisions

| decision | reason |
|---|---|
| Speech and vision fused as `senses` | models are converging on one live session that hears, sees and speaks; one session, one clock, no sibling lockstep |
| The session is I/O only; the loop lives outside | removes the duplicated handler/tool/run loop; the engine owns agent loops |
| Live and cascaded modes | live is the fast path; cascaded gives any engine agent a voice, vendor- and model-neutral |
| No store | the thread is the conversation log, the Refinery the agent's log; a third log would repeat them |
| `LiveModel`, `TranscriptionModel`, `SpeechModel`; `TurnDetector` cut | named for what they produce; turns split into the transcriber's end-of-utterance and an optional decision-model check |
| One live contract, no capability matrix | adapters raise what their vendor cannot do |
| `prompt` / `inform` primitives | a text mind steering a live voice needs to ask it to speak and to tell it what changed; connect-time instructions go stale |
| `look` returns image parts | the text mind sees directly; no separate vision model session |
| `say` returns what was heard | the model learns it was interrupted and what got through |
| `say` takes a `str` or an `AsyncIterator[str]`; the `say` tool stays text | a text mind's streamed reply starts playing on its first sentence; a model's tool arguments are a string |
| SensesTools for the text mind; the live model takes any `Tools` | most of what a live model needs is other family tools |
| WebSocket core, WebRTC as an extra | WebRTC is quality-critical for browser voice (Opus, loss concealment, echo cancellation); a plain install stays light |
| Transcripts mirrored to a thread by consumer glue | the libraries compose through shared shapes and never import each other |
| An empty attribution queue is `triggered_by=None` | declared, never assumed: a live model answering the person is not the assistant acting on its own |
| Every action leaves an event with its cause (`Looked`, `Muted`, `Informed` added) | a record of who looked through the camera, gated the voice or told the model something, mirrored like the rest |
| `serve` returns the transport; the consumer builds the session | no session-factory callback; the loop stays the consumer's |
| A four-method media connection (`receive() -> str \| bytes`) | text and binary frames interleave on one socket |
| The utterance number rides in the audio header | stale frames are dropped in the client as well as the server |
| ~~Authentication is the hello's token only~~ — superseded by the next row | |
| Authentication lives at the consumer: `serve(connection, identity=, scope=)` and `accept_offer(sdp, identity=, scope=)`; the hello carries only the protocol version; no `authenticate`, no deadline | the consumer's framework already authenticates HTTP and upgrades; senses never sees a credential; the cross-site hijacking risk is closed by the consumer's `Origin` check or tokens, documented as a checklist; mirrors rfnry-thread |
| The WebRTC client sends its `hello` on the data channel | the protocol version is checked on both transports; the offer body stays `{sdp}` |
| `setFps(fps)` on the TypeScript connection | a product raises or lowers the rate models see while the camera runs, without reconnecting |
| Video is frames at the client's `fps`: JPEG over WebSocket, a video track over WebRTC | live models take video as image frames; WebRTC's inter-frame compression serves higher rates; true video input would add `send_video` additively |
| Live tools are given at `start(tools=)`, not to `Session(...)`; `start(tools=)` without a live model is a `ConfigurationError` | the two minds are circular — the live model's `consult` tool runs an agent whose `SensesTools` need the session — so the session is built first and its tools given when the live connection opens, the moment vendors take tool definitions; a cascaded session's tools belong to the consumer's loop |
